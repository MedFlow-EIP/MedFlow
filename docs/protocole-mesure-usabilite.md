# MedFlow Protocole de mesure d'usabilité (Mesure de départ)

À faire passer **avant** toute nouvelle modification du produit. Ce protocole doit être réutilisé **à l'identique** en décembre pour la deuxième mesure ne pas le modifier entre les deux.

## Participants
- 5 personnes de la cible (étudiants en médecine)
- **Hors équipe**, n'ayant **jamais utilisé** MedFlow
- Sur leur propre téléphone Android si possible (sinon, le téléphone de test avec l'APK installé), **compte neuf** créé pendant la séance
- Le **même PDF de cours** pour tout le monde, aux deux mesures, déjà présent sur le téléphone

## Déroulé d'une session (~25-30 min)

1. Accueil (2 min) expliquer que c'est le produit qu'on teste, pas la personne ; qu'il n'y a pas de bonne ou mauvaise réponse ; qu'on veut les entendre penser à voix haute.
2. Les 5 tâches, une par une (4-5 min chacune)
3. Questionnaire de satisfaction SUS (5 min) voir document séparé

## Consigne à lire avant de commencer (mot pour mot)

> "Je vais te demander de faire quelques actions dans l'application, comme tu le ferais normalement. Essaie de dire à voix haute ce que tu penses en le faisant pourquoi tu cliques ici, ce que tu t'attends à voir. Je ne vais pas t'aider sauf si tu es vraiment bloqué·e, c'est normal et voulu : je veux voir comment l'app se comporte sans mon intervention."

## Les 5 tâches critiques

Ce qu'un étudiant doit absolument réussir, de l'import d'un cours à la préparation d'un examen. Chaque tâche est un résultat à atteindre, pas une fonctionnalité à trouver.

Pour chaque tâche : lire la consigne exactement telle qu'écrite, chronométrer dès la fin de la consigne, ne pas aider sauf blocage total > 2 min (le noter comme intervention). La génération du cours prend environ une minute : **mettre le chronomètre en pause pendant l'écran de génération**.

### Tâche 1 Avoir des révisions prêtes à partir de son cours
**Consigne à lire** : *"Tu as un cours de médecine en PDF sur ton téléphone. Fais en sorte que l'app te prépare de quoi le réviser."*
**Réussie quand** : le cours généré est ouvert (résumé, flashcards ou quiz visibles).
*(prévoir le PDF de test à l'avance, le même pour tous)*

### Tâche 2 Faire sa révision du jour jusqu'au bout
**Consigne à lire** : *"Révise ce que l'app te propose pour aujourd'hui, jusqu'à la fin de la session."*
**Réussie quand** : l'écran de fin de session est atteint.

### Tâche 3 Comprendre une erreur
**Consigne à lire** : *"Réponds exprès faux à une question de révision, puis fais-toi expliquer pourquoi la bonne réponse est la bonne."*
**Réussie quand** : une explication de la bonne réponse est affichée (explication sous la question ou réponse de l'assistant).

### Tâche 4 Interroger l'assistant sur son cours
**Consigne à lire** : *"Demande à l'assistant de te résumer les points clés du cours que tu viens d'importer."*
**Réussie quand** : l'assistant répond à partir de ce cours.

### Tâche 5 Savoir quoi réviser avant son examen
**Consigne à lire** : *"Ton examen est le 15 janvier. Enregistre-le dans l'app, puis regarde ce que tu dois réviser cette semaine."*
**Réussie quand** : l'examen est enregistré et la prévision de la semaine a été consultée.

*Tâches retirées de la première version : « terminer une leçon d'un parcours » (contenu générique, pas le cours de l'étudiant) et « classement + ami » (utile, mais pas indispensable pour réviser).*

| Tâche | Réussie sans aide (O/N/Partielle) | Temps (mm:ss) | Nb erreurs / retours en arrière | Nb interventions | Notes qualitatives |
|---|---|---|---|---|---|
| 1. Révisions prêtes à partir du cours | | | | | |
| 2. Révision du jour jusqu'au bout | | | | | |
| 3. Comprendre une erreur | | | | | |
| 4. Interroger l'assistant sur son cours | | | | | |
| 5. Savoir quoi réviser avant l'examen | | | | | |

**Définitions** :
- **Réussie sans aide** : la personne arrive au résultat demandé sans intervention. "Partielle" = elle y arrive mais pas de la façon attendue, ou avec beaucoup d'hésitation.
- **Erreur/retour en arrière** : clique sur quelque chose puis fait marche arrière, se trompe d'écran, recommence une action.
- **Intervention** : tu dois donner un indice ou débloquer la personne (bloquée > 2 min).

## Après les 5 tâches
Faire remplir le questionnaire SUS (document séparé), puis poser une dernière question ouverte : *"Comment décrirais-tu cette application à un ami qui ne la connaît pas ?"* (utile aussi pour l'objectif 1 vérifier promesse vs réalité).

## Premier contact

Pendant la tâche 1, noter aussi le **temps jusqu'à la première action réussie** : du premier écran de l'app au lancement réussi du premier import. Noter où la personne hésite ou abandonne avant (inscription, tutoriel, accueil).

## Après les 5 sessions
Compiler les 5 grilles dans un seul tableau (une ligne par participant × tâche), calculer les moyennes de temps et le taux de réussite par tâche. Ça devient la base de la comparaison avec la mesure de décembre.
